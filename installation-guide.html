1

Install Antigravity 2.0

Antigravity is Google's agent-first IDE — it's where we'll write our React app. It runs on macOS, Windows, and Linux.

"Open it. Stare at it lovingly. Then close it. We'll come back."

Step 1.1 Download from the official site

Head to the Antigravity download page and grab the installer that matches your operating system.

🪐 Download Antigravity 2.0 →

Pick the right build

On the download page you'll see options for macOS Apple Silicon, macOS Intel, Windows x64, Windows ARM64, and Linux x64/ARM64. If you're unsure which Mac you have, click the Apple menu → About This Mac.

Step 1.2 Install it

  1. Double-click the downloaded .exe file.
  2. If Windows SmartScreen warns you, click More info → Run anyway.
  3. Click through the installer (defaults are fine). Add to PATH if asked.
  4. Launch Antigravity from the Start menu when done.
  1. Open the downloaded .dmg.
  2. Drag the Antigravity icon into the Applications folder.
  3. Open Applications → right-click Antigravity → Open (only needed the first time, to bypass Gatekeeper).
  1. Extract the downloaded .tar.gz archive to a folder of your choice (e.g. ~/apps/antigravity).
  2. From a terminal, navigate into that folder and run ./antigravity.
  3. Optional: create a desktop entry so you can launch it from your app menu.
Sign in with Google

The first time you open Antigravity, sign in with your personal Google account. You get free access to start.

2

Install Node.js (the easy way)

React + Vite needs Node.js to run. We've written little scripts that check what you already have, install Node.js 24.x if needed, set environment variables, and verify everything works — all in one go.

Why a script?

So we don't lose 30 minutes of class time troubleshooting PATH variables on twenty different laptops. 😅

Step 2.1 Download the script for your OS

🪟
Windows
PowerShell script
setup-node-win.ps1
🍎 🐧
macOS / Linux
Shell script
setup-node-linux-mac.sh
What the script actually does
  • Checks if Node.js is already installed (and if it's the 24.x line).
  • If missing or wrong version: downloads and installs Node.js 24 (LTS).
  • Sets up PATH so node and npm work from any terminal.
  • Verifies the install by running node -v and npm -v.
3

Run the setup script

Find the file you just downloaded (probably in your Downloads folder), then follow the steps for your OS below.

  1. Press Win key → type PowerShell → right-click → Run as Administrator. (Admin is needed because installing Node.js modifies system paths.)
  2. Allow scripts for this session (one-time, only for this PowerShell window): 
    PS> Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
  3. Navigate to where you saved the script (usually Downloads): 
    PS> cd $HOME\Downloads
  4. Run the script: 
    PS> .\setup-node-win.ps1
  5. Wait for the green [OK] messages. When it says "You're ready for the Antigravity session", you're done.
If you see "running scripts is disabled"

That's the SmartScreen / execution policy stopping us. Step 2 above fixes it for the current window only — safe and reversible. After closing the window, your system goes back to normal.

  1. Open Terminal (Cmd+Space → type "Terminal" → Enter).
  2. Navigate to Downloads: 
    $ cd ~/Downloads
  3. Make the script executable: 
    $ chmod +x setup-node-linux-mac.sh
  4. Run it: 
    $ ./setup-node-linux-mac.sh
  5. When you see "You're ready for the Antigravity session", close the Terminal and open a brand-new one — that's what loads the new PATH for future commands.
  1. Open a terminal (Ctrl+Alt+T on most distros).
  2. Navigate to where you saved the script: 
    $ cd ~/Downloads
  3. Make it executable: 
    $ chmod +x setup-node-linux-mac.sh
  4. Run it (no sudo needed — we use nvm, which installs Node into your home folder): 
    $ ./setup-node-linux-mac.sh
  5. Close the terminal and open a new one to pick up the updated environment.
4

Verify your install

Open a fresh terminal (PowerShell on Windows, Terminal on Mac/Linux) and run:

$ node -v
$ npm -v

You should see something like:

# Example output
v24.3.0
10.8.2
The number should start with v24.

If it doesn't (or if you get "command not found"), close every terminal window, open a fresh one, and try again. The script updates your PATH, but already-open terminals don't see those updates until they're restarted.

5

Create a Firebase project

Firebase Hosting is Google's free static-site hosting. We'll create a project, enable Hosting, and connect it to our React app.

Step 5.1 Open the Firebase console

Visit console.firebase.google.com and sign in with the same Google account you'd like the project to live under.

Step 5.2 Add a new project

The Firebase console — your project dashboard lives here.
  1. Click the "Create a project" tile (or "Add project" if you already have others).
  2. Give it a memorable name — e.g. teacher-workshop-2026. Firebase appends a unique suffix automatically.
  3. When asked about Google Analytics: you can disable it for this workshop (faster setup). Toggle it off and click Create project.
  4. Wait ~30 seconds while Firebase provisions everything, then click Continue.

Step 5.3 Enable Firebase Hosting

  1. In the left sidebar, expand Build, then click Hosting.
  2. Click Get started.
  3. You'll see a 3-step setup screen. The console gives you commands to run — we'll run them through our own scripts and the terminal, so just click Next through this wizard. (You can dismiss it; the actual work happens on your machine.)
Build → Hosting → Get started
Pro tip: write down your project ID

Look at the top of your Firebase console — your project ID looks like teacher-workshop-2026-a1b2c. You'll need it in the next steps.

6

Install & log in to Firebase CLI

The Firebase CLI is a small command-line tool that talks to Firebase from your computer. We'll install it globally via npm — which works the same on every OS.

Step 6.1 Install firebase-tools globally

In a terminal (any OS), run:

$ npm install -g firebase-tools
The -g flag

That tells npm to install the package globally — meaning the firebase command will be available from any folder, not just one project.

Permissions on macOS/Linux

If you see EACCES errors, it usually means npm is trying to write to a system folder. Our setup script uses nvm, which puts Node in your home directory — so global installs should "just work" without sudo.

Step 6.2 Verify the CLI works

$ firebase --version

Step 6.3 Log in to your Google account

$ firebase login

This will:

  • Ask whether you want to share usage data (your call — saying "No" is fine).
  • Open your browser to the Google sign-in page.
  • Sign in with the same account you used to create the Firebase project.
  • Show "Success! Logged in as ..." in the terminal when done.
Sanity check

Run firebase projects:list — you should see your workshop project in the list. If you do, the CLI and your account are talking. 🎉

7

Initialize Firebase in your React app

By this point you should have a React + Vite app in Antigravity. If not, here's the one-liner to scaffold one:

$ npm create vite@latest my-workshop-app -- --template react
$ cd my-workshop-app
$ npm install

Step 7.1 Run firebase init

From the root of your React project (the folder with package.json in it), run:

$ firebase init

Step 7.2 Answer the prompts

The CLI will ask you a series of questions. Here's exactly what to answer:

Which Firebase features do you want to set up?
Use the arrow keys to move, spacebar to select, then Enter. Select only: ◉ Hosting: Configure files for Firebase Hosting
Project Setup → Please select an option:
Pick Use an existing project
Select a default Firebase project for this directory:
Choose the workshop project you created earlier (e.g. teacher-workshop-2026-a1b2c)
What do you want to use as your public directory?
Type dist — this is where Vite puts the built output. Don't accept the default public.
Configure as a single-page app (rewrite all urls to /index.html)?
Type y — React Router and SPA navigation need this.
Set up automatic builds and deploys with GitHub?
Type N — we'll deploy manually from the terminal today.
File dist/index.html already exists. Overwrite?
If asked, type N — we want Vite's index.html to be used, not Firebase's template.

When the wizard finishes, you'll see two new files in your project root:

  • firebase.json — hosting configuration
  • .firebaserc — links this folder to your Firebase project
Why dist and not public?

Vite outputs your production build to dist/. The public/ folder is for static assets that get copied in as-is. If you tell Firebase to deploy public/, your built React app won't be there — you'll deploy an empty index.html. Common mistake. ✋

8

Build & deploy 🎉

Two commands. That's it.

Step 8.1 Build the production bundle

$ npm run build

This runs Vite's production build. When it finishes, you'll have a dist/ folder full of optimized HTML, JS, and CSS.

Step 8.2 Deploy to Firebase

$ firebase deploy

Firebase uploads your dist/ folder, configures hosting, and gives you a live URL. The output will look something like:

=== Deploying to 'teacher-workshop-2026-a1b2c'...

i  deploying hosting
i  hosting[teacher-workshop-2026-a1b2c]: beginning deploy...
i  hosting[teacher-workshop-2026-a1b2c]: found 8 files in dist
✔  hosting[teacher-workshop-2026-a1b2c]: file upload complete
i  hosting[teacher-workshop-2026-a1b2c]: finalizing version...
✔  hosting[teacher-workshop-2026-a1b2c]: release complete

✔  Deploy complete!

Hosting URL: https://teacher-workshop-2026-a1b2c.web.app

Open that Hosting URL in your browser — your React app is live on the internet. 🌍

Iterate & redeploy

Change your code in Antigravity → run npm run build → run firebase deploy. Same two commands every time. The URL stays the same.

Bonus Useful follow-up commands

# Preview locally before pushing
$ firebase emulators:start

# Deploy only hosting (skip other Firebase products)
$ firebase deploy --only hosting

# See what's currently deployed
$ firebase hosting:channel:list

# Make a preview channel (shareable test URL)
$ firebase hosting:channel:deploy preview-branch-name
9

If something breaks…

"node is not recognized" / "command not found"

You're in a terminal that was open before Node was installed. Close it, open a new one. If it still fails on Windows, restart your computer.

"firebase: command not found" after install

Same fix — close the terminal, open a new one. On macOS/Linux, run npm config get prefix to see where global packages go, and make sure that path is on your PATH.

The deployed URL shows a blank page

You probably told Firebase to use public instead of dist. Open firebase.json and change "public": "public" to "public": "dist", run npm run build again, then redeploy.

The deployed URL shows the "Firebase Hosting setup complete" page

That means Firebase's placeholder index.html got deployed instead of your React app. Delete the dist/index.html Firebase created during init, run npm run build to regenerate from your real source, and redeploy.

"Error: HTTP Error: 403"

Run firebase logout, then firebase login --reauth. Make sure the account you sign in with is the same one that owns the Firebase project.
